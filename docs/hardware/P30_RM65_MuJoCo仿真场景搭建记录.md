## 3. 可达区域（`reach_mask.json`）

判据：位置到达 + 工具轴竖直朝下 + 关节限位内 + 无碰撞，**yaw 自由**（5 自由度）。
网格 0.02 m，24 × 37 = 888 点（范围由 `mount.yaml` 的台面 + 物体范围外扩 0.10 m 推导）。

- **可抓 601 / 888（67.7%）**
- 形状：x ∈ [0.42, 0.64] 的带状区，|y| 越大越窄
- 最大内接矩形：x ∈ [0.42, 0.64] × y ∈ [−0.28, 0.28] = 0.22 × 0.56 m
- 抓取高度：`grasp_site` z = 台面 + `CUBE_HALF` + `GRASP_SITE_UP` = **0.616 m**

> **高度必须和采集一致（2026-11-04 修复）**：脚本曾硬编码
> `TABLE_TOP_Z + 0.03 + 0.002 = 0.582`，比采集实际用的 `grasp_z_for()`
> （0.616）低 34 mm。两个不同 z 平面算出的可达区不能用来证明采集范围有效，
> 而且会低估可抓面积（当时报 46.2%）。现在直接调用 `grasp_z_for()`，
> 网格范围也从 `mount.yaml` 推导，不再有硬编码。

> 早期用「关节空间随机采样 + KD-tree 近邻」估可达区，得到大量自相矛盾的
> 结果（同一行 y=+0.10 全空、y=+0.15 却有命中）。根因是竖直姿态在 400k
> 样本里只占 2.2%，按 z 切片后每层不足 200 点，二维平面平均间距 5cm，
> 用 1.2cm 容差判定必然产生假阴性。**必须用真 IK**。

## 4. 踩过的坑（按严重程度排序）

### 4.1 MuJoCo 相机前向是 **−zaxis**（最坑）

`<camera zaxis="...">` 的属性值等于 `cam_xmat` 的**第 3 列**，而相机沿
OpenGL 约定看向 **−第 3 列**。即：

```
前向 f = −cam_xmat[:, 2] = −zaxis
```

搞反的后果：`head_cam` 和 `wrist_cam` 全部朝后上方看，渲染出来只有天空。
而且所有投影几何检查（用 `cmat.T @ (p − cpos)` 的第 2 分量当深度）也跟着错，
检查说"可见"、渲染说"看不到"，白折腾了三轮。

**正确写法**：先求期望前向 `f`（例如 look-at），再令 `zaxis = −f`。
投影时深度 = `−(cmat.T @ (p − cpos))[2]`。

验证脚本：`cam_axis_test.py`（球放在 ±x/±y/±z 六个方向，看哪个出现在图心）。

### 4.2 姿态误差不能用 `0.5 * Σ cross(Rc_i, Rt_i)`

这是 `sin(θ)` 向量，**θ=0° 和 θ=180° 都返回 0**。IK 会收敛到
「夹爪完全倒转 180°」的假解，还报告 `total=0`。

症状：实测出现 `total=0.000000` 但 `angle_err=180.00°`。

**正确做法**：用 6D 旋转表示（旋转矩阵前两列之差），或直接用轴向量之差。
本项目的 `ik_core.py` 用 5 自由度约束（位置 3 + 轴向量 3），天然无此问题。

### 4.3 IK 不能过度约束 yaw

抓方块不需要指定绕垂直轴的 yaw：
- Dex1-1 两指对称，`joint6` 可 ±360° 转
- 方块有 90° 旋转对称

强行约束完整 6D 姿态会把 yaw 也钉死，在腕部接近奇异时与位置约束冲突
→ 超定 → 内部点误判不可达（实测同一目标点：约束 6D 时 err=0.0059，
只约束 5D 时 err=0.00000）。

### 4.4 关节空间插值必须来自同一 IK 分支

`ik.solve()` 用随机多起点，同一个目标点两次调用可能收敛到不同分支
（实测 joint4 相差 **180.3°**、joint3 相差 93.5°）。对这样两组解做
线性插值，机械臂会绕大圈，插值到 t=1.0 时 `grasp_site` 仍差 15cm。

**正确做法**：`ik_core.solve_near()` / `solve_chain()` —— 用上一点的解作
种子解下一点，保证同分支。修正后关节最大变化从 180° 降到 25°。

### 4.5 夹爪开合方向与直觉相反

`gripper_left_joint` 轴是 `−x`，`gripper_right_joint` 轴是 `+x`，
**`q` 越小越张**：

| `q` | 指垫中心距 |
|---|---|
| −0.020 | 12.7 cm（张开） |
| +0.0245 | 3.8 cm（闭合） |

写反了会变成「以为张开其实闭合」，下探时把方块推走（实测方块 x 从
0.505 漂到 0.536）。

### 4.6 `grasp_site` 不能直接对准方块中心

`grasp_site` 比夹爪最低点高 **3.6cm**。若直接对准方块中心（z=0.58），
指垫下半部会插进台面，IK 因此判定碰撞不可达。

**正确做法**：目标 z = 方块中心 + 0.036 = 0.616。

### 4.7 躯干碰撞盒高度必须等于实测最高点

最初写 `pos="-0.005 0 0.06" size="0.40 0.14 0.14"`，顶面到 z=0.80，
而实测躯干最高点只有 0.754，且臂基座 z=0.78 —— 臂基座整个嵌在虚高的
碰撞盒里，侧向摆动全被判干涉。

**正确值**：`pos="-0.005 0 0.015" size="0.40 0.14 0.139"`（顶面 = 0.754）。

### 4.8 腿关节没有驱动器时必须加弹簧

对应真机「不允许直接控制关节」的约束，场景里腿关节没有 actuator。
若只在关键帧设好体位而不加 `stiffness`/`springref`，重力会让腿慢慢下垂。
实测加 `stiffness=800/1200/1200/200` 后，静置 3 秒腿关节偏离 < 0.85°、
躯干零漂移。

### 4.9 MuJoCo 3.x 移除了 geom 级 `scale`

镜像腿部 mesh 必须用 **asset 级** scale：

```xml
<mesh name="thigh_L" file="FL_THIGH.STL"/>
<mesh name="thigh_R" file="FL_THIGH.STL" scale="1 -1 1"/>
```

同理 `<camera>` 也不支持 `resolution` 属性。

### 4.10 过曝会毁掉颜色条件

初始 headlight `ambient=0.35 diffuse=0.55` 加上两盏方向光，渲染亮度到
0.877、平均饱和度只有 0.067，彩色方块接近白色。

修正后 `ambient=0.18 diffuse=0.42` + 方向光 `0.45/0.22`，亮度降到 0.75、
饱和度升到 0.11，四色每色 720~4000 px 稳定可辨。

### 4.11 头部相机不能只做视锥检查

第一版 `head_cam` 装在躯干后部 `x=0.02`，视锥检查 25/25 全通过，
但渲染出来只能看到夹爪 —— 因为相机到台面的视线正好穿过装在 `x=0.30`
的机械臂。**必须用 `mj_ray` 做真实遮挡检测**，且要在「手臂处于抓取位」
时评估（训练时这才是主要工况）。

### 4.12 头部相机不能只要求覆盖台面

要求覆盖整张台面会把相机逼到 z=1.69 m，方块在图里只剩 45 像素，
颜色特征基本消失。正确要求是覆盖**物体可能出现的可达区**，
这样相机能拉近到世界 z=1.12，方块约 100 像素。

## 7. 换安装位置的标准流程

`configs/mount.yaml` 是唯一真源。拿到实际安装参数后：

```bash
# 1. 改 configs/mount.yaml 的 mount / trunk_top_z / table 段
python .tmpm/run.py --push-configs "echo pushed"   # 从本地推到 Thor

# 2. 一键重建（场景 + 可达区 + 范围校验，约 3 分钟）
python .tmpm/run.py "cd /home/user/rm_test/sim/p30_rm65 && MUJOCO_GL=egl python3 -u remount.py"

# 3. 物理闭环复验（可选，约 1 分钟）
python .tmpm/run.py "cd /home/user/rm_test/sim/p30_rm65 && MUJOCO_GL=egl python3 -u remount.py --verify"

# 4. 试采 4 条（Thor 屏幕上带窗口看）
python .tmpm/run.py "cd /home/user/rm_test/sim/p30_rm65 && DISPLAY=:1 XAUTHORITY=/run/user/1000/gdm/Xauthority MUJOCO_GL=glfw python3 -u collect_color_grasp.py --num 4 --out data/try --view"

# 5. 全量 150 条 + 导出 + 校验
```

`remount.py` 会明确告出 `objects` 范围的可行上下界（可达区 ∩ 台面内缩 `cube_half`），
范围越界时直接标红——**不要手改硬编码**，那是 2026-11-04「方块悬空翻落」事故的成因。
