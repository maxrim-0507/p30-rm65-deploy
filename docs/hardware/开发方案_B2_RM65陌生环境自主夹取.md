## 1. 项目概述

### 1.1 任务定义

- **本体**：Unitree B2（四足移动平台）+ REALMAN RM65（6 轴机械臂，负载 5 kg，工作半径 610 mm）
- **任务**：在**无先验地图的陌生环境**中，根据自然语言指令（如"抓那个红色杯子"）**自主**完成：环境定位 → 搜索目标 → 导航逼近 → 机械臂抓取 → 交付/放置。
- **执行形态**：**分步式技能串联**（导航 → 停下 → 抓取），非实时边走边抓。

### 1.2 技术路线定位

本方案对应「人形机器人运动智能知识库」中的 **LocoManip（移动操作）** 路线，采用两种组织方式的混合：

1. **技能串联**：四足导航、机械臂抓取、夹爪控制各自独立，由状态机编排；
2. **生成与规划式**：上层大模型/VLA 负责"理解指令 + 定位物体 + 生成抓取目标"，底层 MoveIt2 / ros2_control 负责执行。

同时遵循知识库的 **System 0 / System 1 分工**：

- **System 1（上层智能）**：VLM/VLA —— 语言解析、开放词汇物体定位、抓取目标/动作生成；
- **System 0（快速身体控制）**：导航、运动规划、关节级执行、安全约束。

### 1.3 成功标准

| 指标 | 目标 |
|---|---|
| 陌生环境建图/重定位 | 首次进入 5 分钟内完成建图并可用 |
| 导航成功率 | 到达目标附近（±0.3 m 内）> 90% |
| 抓取成功率 | 指定物体（未见类别，路线 A）> 70%；VLA 路线单任务 > 80% |
| 失败恢复 | 空抓/丢失/碰撞均能回收到状态机并重试或回报 |

## 5. 关键设计决策

### 5.1 分步式 vs 实时协同

选择**分步式**，理由：

- 四足停稳后 `map → base_link` 的实时抖动不再影响抓取精度；
- 各模块（导航/抓取）可独立调试、独立验收；
- 固定基座采集的 VLA 数据，可直接迁移到移动平台"停下抓取"阶段。

### 5.2 VLA 的集成深度

端到端 VLA 在移动平台上有天然边界：现成 VLA 输出的是机械臂末端相对动作，隐含"臂基座固定"假设，泛化不到"导航找东西"阶段。因此：

- **导航阶段始终交给 SLAM + Nav2**，VLA 不参与；
- **VLM** 负责"指定物体"的语言理解 + 开放词汇检测/分割定位；
- **抓取姿态** 两条路线（详见 [第 7.3 节](#73-6d-抓取姿态生成与选择) 与 [第 8 节](#8-vla-端到端路线进阶)）：
  - **路线 A（起步推荐）**：VLM 定位 → 裁剪点云 → 6D 抓取网络 → MoveIt2 规划；
  - **路线 B（进阶）**：端到端 VLA 输出动作块，替换"抓取网络 + MoveIt"。

### 5.3 移动操作坐标对齐

分步式「停下再抓」正是用来规避移动-操作耦合。抓取链：

```
末端相机看到物体 → 手眼标定变换到 end_effector → FK 到 arm_base → MoveIt 规划 → 执行
```

## 6. 分步式状态机流程

```
① 语言指令（"抓桌上那个红色的杯子"）
   ↓ VLM 解析 → 目标物体语义描述 + 期望区域
② 陌生环境定位：LiDAR SLAM 建图/重定位（首次进入先建图）
③ 探索/导航：Nav2 带四足在环境中搜索目标（不知道位置则主动视觉搜索）
④ 逼近停下：四足导航到物体附近安全距离 → 停止行走（锁死 base）
⑤ 手眼识别：末端相机 + VLM 定位物体，裁剪点云
⑥ 抓取姿态：6D 抓取网络（或 VLA）输出抓取位姿
⑦ 运动规划：MoveIt2 + OMPL 规划无碰撞轨迹（rm_models 做碰撞检测）
⑧ 抓取执行：ros2_rm_robot 执行轨迹，夹爪闭合（电流反馈判接触）
⑨ 拿起 → 交付/放置（可选）
⑩ 返回或继续下一个任务
```

## 7. 自主抓取详细实现

自主抓取是一条**「像素里的物体 → 机械臂可执行的关节轨迹」**的闭环，分五段：

```
末端相机(RGB-D) ──①──> 物体定位(VLM) ──②──> 坐标变换(手眼) ──③──> 6D抓取姿态
      ▲                                                              │
      │                                                              ▼
  ④失败重试 <── ⑤夹爪闭环(力/电流判接触) <── 执行(MoveIt2) <── 抓取轨迹规划④
```

核心问题：**VLM 给出像素级信息，MoveIt2 需要基座坐标系下的 6D 位姿**。

### 7.1 物体定位（VLM 开放词汇检测 + 分割）

```
语言指令 "红色杯子" ──> GroundingDINO(文本 prompt) ──> 2D bbox
                          └──> SAM(以 bbox 为提示) ──> 像素级 mask
                                                            │
                                      深度图 + 相机内参 ──> 反投影
                                                            ▼
                                            物体在相机坐标系的 3D 点云
```

**技术栈**：`Grounded-SAM`（GroundingDINO + SAM）是主流开放词汇感知组合；也可用多模态 VLM（Qwen2.5-VL / GPT-4V）直接输出目标 bbox 或指代坐标（更省事但更慢）。

**深度反投影**（mask → 3D）：

```python
def mask_to_pointcloud(mask, depth_img, intrinsics):
    """像素 mask + 深度图 -> 相机坐标系 3D 点云"""
    ys, xs = np.where(mask > 0)
    z = depth_img[ys, xs] / 1000.0          # mm -> m
    valid = (z > 0.2) & (z < 1.5)
    ys, xs, z = ys[valid], xs[valid], z[valid]
    x = (xs - intrinsics.cx) * z / intrinsics.fx
    y = (ys - intrinsics.cy) * z / intrinsics.fy
    return np.stack([x, y, z], axis=1)       # (N, 3) 相机坐标
```

> 只对 mask **中心 30% 区域**取深度（或取最小值/中位数），避免 mask 边缘混入背景深度。

### 7.2 坐标变换（手眼标定矩阵链）

物体从**相机坐标系**变到**机械臂基座坐标系**：

```python
# 手眼标定结果（眼在手，标定一次持久有效）
T_cam2ee = np.load("hand_eye_matrix.npy")      # 4x4，来自睿尔曼 hand_eye_calibration

# 正运动学：当前关节角 -> 末端在 base 的位姿
T_ee2base = forward_kinematics(q_current)       # 用 MoveIt / rm_models 的 URDF

# 物体中心从相机系 -> 基座系
obj_center_cam = pointcloud.mean(axis=0)
obj_center_base = (T_ee2base @ T_cam2ee @ np.append(obj_center_cam, 1.0))[:3]
```

标定用睿尔曼官方 `hand_eye_calibration`（RM65 + D435，眼在手）：末端装 ArUco 标定板，机械臂多姿态拍照，`cv2.solvePnP` + 手眼方程（AX=XB）解出 `T_cam2ee`。

### 7.3 6D 抓取姿态生成与选择

从物体点云生成**可执行的抓取位姿**（位置 + 姿态 + 夹爪开度），而非"bbox 中心 + 垂直下降"。

| 路线 | 原理 | 适用 |
|---|---|---|
| **VLA 输出抓取动作** | 输入末端相机图 + 语言指令，直接输出末端相对位姿序列/动作块 | 进阶，需遥操作数据 |
| **6D 抓取网络** | 输入物体点云，输出抓取候选 + 得分（GraspNet-1B、AnyGrasp、Contact-GraspNet） | **起步推荐**，开箱即用 |
| 几何法（无学习） | RANSAC 桌面分割 + DBSCAN 聚类 + PCA 主轴 → 规则抓取 | 简单物体够用 |

**起步推荐组合**：VLM 定位（7.1）→ 裁剪物体点云 → 喂给 **AnyGrasp 或 GraspNet** 输出候选 → 排序选最优。

```python
def generate_grasp(obj_pointcloud, scene_pointcloud):
    # 1. 6D 抓取网络输出候选（位姿 + 夹爪开度 + 得分）
    grasp_candidates = grasp_net.infer(obj_pointcloud)

    # 2. 逐个候选做可达性 + 碰撞过滤
    for g in sort_by_score(grasp_candidates):
        q = move_group.ik(g.pose, current_joints)   # 可达性：IK 是否有解
        if q is None:
            continue
        if collision_check(g.pose, scene):          # 碰撞：用 rm_models URDF
            continue
        return g.pose, g.width, q
    return None                                     # 全失败 -> 触发重试/换视角
```

选择准则优先级：**得分 → IK 可达 → 无碰撞 → 离当前末端最近**。

### 7.4 抓取轨迹规划（MoveIt2 两段式）

**不能一步到位**，分两段：先到抓取点上方再垂直下降，避免撞物体。

```python
from moveit_py import MoveGroupInterface

move_group = MoveGroupInterface("arm", "robot_description")

# 1. pre-grasp：抓取位姿沿接近方向回退 10cm（同姿态）
pre_grasp_pose = grasp_pose.copy()
pre_grasp_pose.position.z += 0.10

# 2. 关节空间规划到 pre-grasp（自由路径，可绕障碍）
move_group.set_pose_target(pre_grasp_pose)
plan1 = move_group.plan()                      # OMPL RRT-Connect

# 3. 笛卡尔直线下降到 grasp（末端沿直线垂直下降）
waypoints = [pre_grasp_pose, grasp_pose]
plan2 = move_group.compute_cartesian_path(waypoints, eef_step=0.005)

# 4. 执行（接近阶段降速）
move_group.execute(plan1)
move_group.execute(plan2, velocity_scaling_factor=0.2)
```

**两段式意义**：pre-grasp 之前用 RRT 自由绕障；最后 10cm 必须笛卡尔直线，因为夹爪已在物体正上方，任何关节插值的横向偏移都可能撞飞物体。

### 7.5 执行与夹爪闭环（力/电流反馈判接触）

闭合夹爪不能盲目闭到死，用反馈判断是否真的抓住：

```python
gripper.close(target_force=50)         # 设定夹持力上限
# 轮询：位置停止但电流上升 -> 已夹住；位置闭到最小且电流低 -> 空抓
while not gripper.is_done():
    pos = gripper.read_position()
    current = gripper.read_current()
    if current > touch_threshold and pos > min_open:
        detected_grasp = True
        break
if not detected_grasp:
    return RETRY   # 空抓 -> 回到 7.1 换视角/换抓取姿态重试
```

## 8. VLA 端到端路线（进阶）

与路线 A 的本质区别：**省掉显式的抓取姿态估计 + 运动规划，模型直接从像素 + 语言学到动作**，代价是需要自己采真实示范数据。

### 8.1 VLA 架构原理

一个 VLA 模型由三件套组成：

```
┌─────────────────────────────────────────────────────────────┐
│  VLA = 视觉编码器 + 视觉语言主干(VLM) + 动作头(action head)   │
│                                                             │
│  末端相机 RGB ──> 视觉编码器 ──> 视觉 token                   │
│  语言指令     ──────────────────> 文本 token                  │
│  本体状态     ──────────────────> 状态编码 ──┐               │
│                                              ▼               │
│                    VLM 主干(交叉注意力融合) ──> 隐表示          │
│                                              │               │
│                                              ▼               │
│                          动作头(解码动作) ──> 动作输出          │
└─────────────────────────────────────────────────────────────┘
```

**动作表示是 VLA 最关键的分叉**，决定了"模型输出什么、怎么训练、怎么执行"：

| 范式 | 输出形式 | 代表工作 | 特点 |
|---|---|---|---|
| 连续回归 | 末端相对位姿增量（ΔEE，6 维）+ 夹爪 | 早期 BC 策略、LeRobot 默认 | 最简单，直接回归；单峰高斯难表达多模态抓取 |
| 离散动作 token | 连续动作 bin 化 / VQ-VAE 潜动作 | RT-2、OpenVLA、WholeBodyVLA(LAM) | 复用 VLM 的 token 生成能力；量化有精度损失 |
| 扩散 / flow matching | 动作块加噪 → 回归速度场 → 积分去噪 | GR00T N1、π0、MotionWAM | 能表达多模态分布，最稳；推理需多步积分，更慢 |
| motion token | 统一离散全身 token + 连续通道 | MotionWAM（SONIC 64 维）、WholeBodyVLA | 把移动+操作压进同一动作空间，适合全身 |

**动作块（action chunking）** 是几乎所有现代 VLA 的标配：

```
一次推理预测未来 H 步动作 → 只执行前 k 步 → 用新观测重新推理（receding horizon）
```

作用有二：① 掩盖 VLA 推理延迟（执行 k 步期间异步算下一块）；② 时序更平滑，避免逐帧独立推理的抖动。典型取值 H=8~16，k=H/2。

### 8.2 主流基座模型架构对比

| 模型 | 架构 | 动作表示 | 对本项目适配 |
|---|---|---|---|
| **OpenVLA**（7B） | Prismatic VLM + DINOv2/SigLIP 视觉编码器 + 离散动作头 | 256-bin 离散 token | **首选起步**：开源、LoRA 微调便宜、LeRobot 生态成熟 |
| **GR00T N1** | 双系统：Eagle-2 VLM（System 2）+ DiT flow matching（System 1）+ 本体适配器 | 连续动作块（flow） | 适合：跨本体共享动作模块，N1.7 支持 LeRobot + TensorRT 导出 |
| **π0** | 单主干 VLM + flow matching | 动作块（flow） | 效果好但授权门槛高 |
| **WholeBodyVLA** | VQ-VAE 潜动作(LAM) + VLM + 低层 LMO 策略 | 离散潜动作 + 离散移动命令 | 思路借鉴：移动+操作分频 |
| **MotionWAM** | Video DiT + Motion DiT | 统一 motion token | 思路借鉴：世界模型特征辅助动作生成 |

**GR00T N1 的双系统架构**（知识库 P060）最值得理解——它直接对应本方案 System 0/1 分工：

- **System 2**（Eagle-2 VLM）：低频理解图像与指令；
- **System 1**（DiT）：用 flow matching 把语义条件转成连续动作块，最高 120 Hz 闭环；
- **本体适配器**：每个本体独立的 state encoder / action encoder / action decoder，把不同维度（人形/双臂/单臂）投影到共享 DiT。**这是 RM65 单臂接入的关键**——只需换适配器，共享动作生成器不用重训。

### 8.3 数据采集（遥操作）

**官方起点**：

- 睿尔曼 `Touch-Teleoperation-RM65`：RM65 触控式遥操作，连接"人手输入 → 运动映射 → 执行"；
- 宇树 `xr_teleoperate` / `kinect_teleoperate`：遥操作 + 观测-状态-动作记录（采集协议可借鉴）。

**采集闭环**：

```
人手操作遥操作设备 ──> 运动映射 ──> RM65 真实执行
        │                            │
        └────── 每步同步记录 ─────────┘
        观测: 末端相机 RGB 帧 + 当前关节角
        动作: 人手此时给出的末端指令（相对位姿增量）
```

**遥操作设备选型**（从简到繁）：

| 设备 | 成本 | 采集质量 |
|---|---|---|
| 睿尔曼触控面板 / 手机 App | ￥0 | 低，适合验证链路 |
| 力反馈手柄（SpaceMouse / Geomagic Touch） | 低 | 中，6D 直观 |
| 主从机械臂 | 高 | 高，动作最接近执行空间 |
| VR 手柄 + 头显 | 中 | 中，直观但集成重 |

**采集建议**：

| 项 | 建议 |
|---|---|
| 数量 | 单任务先 **50~100 条示范**验证，再扩到几百条 |
| 多样性 | 不同物体、不同初始位姿、不同光照、**含失败重试轨迹** |
| 频率 | 10~30Hz（与推理/控制频率对齐） |
| 语言标注 | 每条示范配一句指令文本 |
| 观测-动作同步 | 相机帧与动作必须时间戳对齐，否则训练错位 |

> **关键**：失败后恢复的轨迹也要录。只录成功轨迹，模型学不会"抓空了怎么调整"。

### 8.4 数据格式与训练

**数据格式**：走 **LeRobot（HDF5）** 生态（VLA 社区事实标准，宇树 `UnifoLM-VLA` 与 GR00T N1.7 均用此管线）。

```python
# 一条示范 = 时间对齐的观测-动作序列
{
  "observation.images.cam_ee":   [T, H, W, 3],   # 末端相机 RGB
  "observation.state.joint_pos": [T, 6],         # RM65 当前关节角
  "observation.state.gripper":   [T, 1],         # 夹爪开度
  "action":                      [T, 7],         # 末端相对位姿(6) + 夹爪(1)
  "language_instruction":        "抓红色杯子",
}
```

**训练方式**：行为克隆（BC）——让模型模仿示范动作，这是 VLA 抓取的主流监督信号（无 RL 奖励设计）。

**LoRA 微调技术细节**：

```python
from lerobot.scripts import train
train(
    policy="openvla",
    dataset="rm65_grasp_v1",
    output_dir="outputs/rm65_vla",
    batch_size=8,
    lora_rank=32, lora_alpha=64,             # LoRA 低秩适配，冻结 VLM 主干
    target_modules=["q_proj", "v_proj"],     # 只微调注意力投影
    lr=2e-5, epochs=20,
)
```

- **冻结 VLM 主干 + LoRA**：省显存（7B 模型单卡可训），且保留预训练视觉语言能力；
- **动作头全量训练**：动作头随机初始化，需从头学；
- **动作块损失**：L1/L2 回归作用在整块上（连续动作）或交叉熵（离散 token）。

**数据金字塔**（GR00T N1 的 Data Pyramid，P060）——不是"数据越多越好"，而是分层：

```
网络视觉语言数据（广泛语义）→ 人类视频（潜动作/IDM 伪标签）→ 仿真/神经视频 → 真机遥操作
预训练跨本体共性 ────────────────────────────────────────────> 后训练专注本体与任务
```

对本项目：直接用 RM65 遥操作数据微调开源基座即可，不必从零采人类视频；若数据不足，可先用仿真（Isaac Lab）生成合成抓取数据预热。

### 8.5 部署推理与延迟优化

采用**服务端推理 + 客户端部署**模式（GPU 主机推理，RM65 客户端执行）：

```python
while running:
    obs = get_observation()            # 末端相机帧 + 当前关节角
    action_chunk = vla_server.predict(obs, instruction="抓红色杯子")
    for i in range(k):                  # 只执行前 k 步，再重新推理
        ee_delta, gripper = action_chunk[i]
        rm65.send_end_effector_delta(ee_delta, velocity_limit=0.3)
        rm65.set_gripper(gripper)
    # 夹爪电流判断接触，空抓则触发"重试"语言指令
```

**延迟优化**（VLA 实时性的关键）：

| 手段 | 效果 | 说明 |
|---|---|---|
| 动作块 + 异步推理 | 掩盖延迟 | 执行 k 步期间算下一块 |
| ONNX / TensorRT 导出 | 2~5× 加速 | GR00T N1.7 官方链路支持 |
| 模型量化（INT8/FP16） | 加速 + 省显存 | 有精度损失需验证 |
| 减小基座（3B 替代 7B） | 大幅降延迟 | GR00T N1.7 即 3B 参数 |

**三个必须处理的问题**：

1. **延迟掩盖**：7B VLA 单次推理 100~500ms，靠动作块 + 异步推理掩盖；
2. **安全**：动作限幅、工作空间软限位、关节限位、力/电流保护、硬件急停——**安全约束在执行层硬编码**，不靠模型自觉；
3. **失败恢复**：夹爪电流/位置判断"抓住没"，没抓住就换"重试"指令再推理。

### 8.6 频率与接口分工（移动操作 VLA 的关键）

这是知识库 P097（WholeBodyVLA）与 P060（GR00T N1）共同强调的核心：**上层 VLA 低频决策，底层高频伺服**，两者接口分频。

| 层 | 频率 | 职责 |
|---|---|---|
| VLA / VLM 上层 | ~10 Hz | "接下来做什么动作"（语义、任务级） |
| 底层伺服 / LMO | 50~120 Hz | "每 20ms 怎样不摔、怎样稳定执行" |

对本项目的意义：即使 VLA 推理抖动或延迟，RM65 底层的关节伺服（`ros2_rm_robot`）仍按 100Hz+ 稳定执行动作块内的插值；VLA 只在"换动作块"时重新决策。**分步式下**，这个分工简化为：VLA 只负责"停下后"的抓取动作序列，四足行走由 Nav2 + 官方步态独立闭环，天然解耦。

### 8.7 移动平台迁移路径

```
① 先把 RM65 固定在工作台上采数据 + 训练 + 跑通 VLA 抓取（排除移动干扰）
        ↓
② 装到 B2 上，用「分步式停下再抓」——停下后 base 固定，观测空间与①一致，
   训练好的 VLA 可直接迁移（分步式带来的最大红利）
        ↓
③ 进阶：若做"边走边抓"，观测加入本体速度/IMU/位姿，动作协调四足，
   属于统一全身策略（参考 WholeBodyVLA / MotionWAM 的全身动作表示），
   数据采集和训练成本翻倍
```

> **边界判断**：阶段③已超出"机械臂 VLA"范畴，进入全身移动操作（loco-manipulation），需要潜动作/motion token 这类统一动作表示，不是把现有 RM65 VLA 直接扩展就能做到的。

### 8.8 已知失败模式（来自论文的真实分析）

| 失败模式 | 来源 | 对策 |
|---|---|---|
| 单末端相机看不到离开视野的物体 | MotionWAM（P081） | 分步式下用四足/机械臂主动换视角；必要时加第二视角相机 |
| 视角偏离训练分布 → 视觉 grounding 失效 | MotionWAM（P081） | 采数据覆盖多视角/多距离；数据增强（随机裁剪/抖动） |
| 人类视频潜动作混入相机运动/不可执行动作 | WholeBodyVLA（P097） | 本项目直接用真机遥操作数据，绕开人类视频问题 |
| 任务记忆/成功检测仍需 Agent 层 | GR00T N1（P060） | 抓取成功判定交给夹爪电流闭环，不依赖模型自报 |
| 不能外推为已解决平衡/长时安全 | GR00T N1（P060） | 平衡交给 B2 官方步态；安全约束在执行层硬编码 |

## 9. ROS2 节点划分

自主抓取不写成一个大脚本，拆成独立节点：

| 节点 | 职责 | 关键接口 |
|---|---|---|
| `object_detector` | VLM 定位 + 分割 + 点云裁剪 | 订阅 `camera/rgb`、`camera/depth`；服务 `/detect_object` |
| `grasp_planner` | 6D 抓取姿态生成 + 选择 | 服务 `/plan_grasp`（输入点云，输出位姿+开度） |
| `manipulation_server` | MoveIt2 规划 + 执行 + 夹爪 | MoveGroup `pick`/action，夹爪服务 |
| `task_sm` | BehaviorTree 状态机（分步式编排） | 调用上述服务，处理失败恢复 |
| `hand_eye_calib` | 标定（离线，一次） | 生成 `T_cam2ee` 矩阵文件 |

用 **BehaviorTree.CPP**（或 `py_trees`）编排——抓取天然有失败分支（空抓、IK 无解、碰撞、物体丢失），行为树比线性脚本更易表达"重试 → 换视角 → 放弃 → 回报"。

## 11. 失败边界与恢复

| 失败 | 原因 | 恢复 |
|---|---|---|
| VLM 未检测到物体 | 视角遮挡、光照 | 机械臂换视角重拍（多视角检测）→ 仍找不到则回报用户指认 |
| IK 无解 | 物体太近/太远/位姿不可达 | 四足微调逼近距离，或换下一个抓取候选 |
| 全部候选碰撞 | 物体靠墙/被包围 | 换抓取候选、换位姿估计、或回报 |
| 空抓（夹到空气） | 抓取位姿误差 > 物体容差 | 夹爪电流判断 → 重试，换候选/重定位 |
| 抓取后滑脱 | 夹持力不足、姿态偏 | 提高夹持力；提升阶段用电流变化判断，失败则放回重抓 |

每个失败都回收到状态机，而非让程序崩掉——这是"自主"与"演示 demo"的区别。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| 四足停下仍有微动/呼吸影响抓取 | 抓取前用末端相机重定位物体，走 eye-in-hand 闭环，不依赖 map 坐标 |
| 陌生环境找不到物体 | Nav2 主动探索 + VLM 指引搜索方向；找不到则回报并请求指认 |
| VLA 泛化差、需大量数据 | 先走路线 A（VLM + 6D 抓取网络），VLA 作进阶 |
| 手眼标定漂移 | 定期用标定板重标；抓取前做视觉重定位校正 |
| 负载/重心 | RM65 + 夹爪 + 相机重量提前核算，必要时配重 |
